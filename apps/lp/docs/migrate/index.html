runelay migrate

One command moves what your agents already have into Runelay, an open source MCP gateway: MCP servers, memories, skills and global instructions.

Run it

Run it on the computer where your agents live, because that is where they keep their files. It logs in through the browser if needed, shows a summary per agent, asks once and sends everything to your server.

$curl -fsSL runelay.com/cli | sh
$runelay migrate

What happens to each MCP server

ResultWhich ones
OAuth accounts with readable tokensArrive connectedGrok; Codex and Claude Code on macOS Keychain
Servers that use headersArrive connectedAny agent
Other OAuth accountsReconnect queue in the panelIncludes Cursor, which encrypts tokens
Local command servers (stdio)Stay on the agentAdd them from the panel if needed

Options and related commands

What it does
runelay migrate --yesSkips the question. Required without a terminal.
runelay migrate --replaceRemoves the migrated MCPs from the agents and leaves only Runelay.
runelay importOnly turns MCP servers from agent configs into connections.
runelay pushSends memories, skills and global instructions.
runelay pullWrites the shared brief and new skills back to the agents.
runelay connectRegisters Runelay in Claude Code, Codex, Cursor and Grok.

Worth knowing

  • Tokens are sent only to your server and stored encrypted.
  • Many providers rotate the refresh token on use. After Runelay refreshes it, the old agent entry may ask for login again; --replace avoids that.
  • Since 0.3.4, running runelay migrate again does not touch connections that already work.
  • runelay pull only edits the block between the Runelay markers in CLAUDE.md and AGENTS.md.

Questions

Which agents does migrate read?

Claude Code, Codex, Cursor, Grok, Gemini and OpenCode.

Does it delete anything from my agents?

Not by default. Only --replace removes the MCP servers it migrated.

Can I run it in CI?

Use runelay migrate --yes, with RUNELAY_URL and RUNELAY_API_KEY set to a key created in the panel.
