A lightweight Obot alternative

Runelay, an open source MCP gateway, and Obot both put MCP servers behind one governed endpoint. Obot is a platform for organizations, with Kubernetes in production; Runelay is for one person's agents, as a desktop app or one container. This page lists what differs, with sources.

Runelay fits when

  • It is your own agents, not a whole company, that need one MCP endpoint.
  • You want a desktop app or a single container, not a Kubernetes cluster.
  • Your agents should share memory as well as accounts and skills.
  • You already have MCP servers in your agents and want to import them with runelay migrate.

Obot fits when

  • Many users need governed access by person or identity-provider group.
  • You need SSO with Entra, Okta or another enterprise provider, and SCIM provisioning.
  • You want an LLM gateway and an MCP gateway in the same platform.
  • You run Kubernetes and want hosted MCP servers as workloads there, or a hosted Obot Cloud.

Questions

Is Runelay a fork of Obot?

No. Runelay is a separate MIT project written with Bun, Hono, SQLite and React.

Do I need Kubernetes to self-host an MCP gateway?

Not with Runelay: the desktop app runs on your computer, and on a server it is one container on any machine with Docker. Obot also runs with Docker for evaluation and recommends Kubernetes for production and multi-tenant use.

Can I move from Obot to Runelay?

Runelay accepts any remote MCP URL, local command or OpenAPI spec, so you can add the servers you use one by one. runelay migrate imports what is configured in your agents, not what is stored inside Obot.
