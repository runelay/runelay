An MCPHub alternative for your own agents

Runelay, an open source MCP gateway, and MCPHub both put many MCP servers behind one endpoint. MCPHub is a hub with a web dashboard, groups and users, usually run with Docker; Runelay runs as a desktop app or one container and also shares skills and memory across agents. This page lists what differs, with sources.

Runelay fits when

  • It is your own agents that need one MCP endpoint, and you want a desktop app with no Docker.
  • Your agents should share accounts, skills and memory, not only tools.
  • You want to add an API from its OpenAPI spec, or connect Google and GitHub with one click.
  • You already have MCP servers in your agents and want to import them with runelay migrate.

MCPHub fits when

  • You want a web dashboard to add, start and watch MCP servers, with logs, latency and health checks.
  • Different teams or projects should get their own group of servers and tools at their own endpoint.
  • Agents should find tools by meaning through Smart Routing, with PostgreSQL, pgvector and an OpenAI-compatible embedding API.
  • Several people sign in with GitHub, Google or your OIDC provider, each with their own credentials.

Questions

Is Runelay a fork of MCPHub?

No. Runelay is a separate MIT project written with Bun, Hono, SQLite and React. MCPHub is an Apache 2.0 project written in TypeScript.

Do I need Docker to run an MCP hub?

Not with Runelay: the desktop app runs on Mac, Windows and Linux, and on a server it is one container. MCPHub recommends Docker and can also run from source with Node.js 22.

Can I move from MCPHub to Runelay?

Runelay accepts any remote MCP URL, local command or OpenAPI spec, so you can add the servers you use one by one. runelay migrate imports what is configured in your agents, not the mcp_settings.json file of MCPHub.
