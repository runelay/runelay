Linear on Runelay, an open source MCP gateway

Linear's official MCP server, shared by every agent. Your agent turns notes into issues, comments on work in progress and reads where a project stands, all under your Linear account.

Linear's own MCP server

The catalog entry points at mcp.linear.app/mcp, the remote server Linear runs. Linear describes it as tools for finding, creating and updating objects in Linear like issues, projects and comments.

Runelay keeps the token and exposes those tools behind your endpoint, so a new agent gets Linear the moment it points at Runelay.

What your agent can do in Linear

  • Issues. Find issues, create new ones and update the ones that exist.
  • Projects. Look up projects and create or update them, for example from a planning document.
  • Comments. Add comments to issues while the agent works.

Try asking

  • “Turn this planning doc into a Linear project with one issue per task.”
  • “Add a comment to the login bug issue with what I found in the logs.”
  • “Summarize what my team finished in the current cycle.”

How it signs in

  • OAuth 2.1 with dynamic client registration. Runelay registers itself with Linear and opens the login; there is no app to create.
  • Scope: the server asks for read write, so the agent acts with your own access in the workspace you approve.
  • One workspace per connection. Linear gives each workspace its own sign-in.

What this connection does

Issues, projects and cycles for your team. Runelay connects to the Linear remote MCP server at https://mcp.linear.app/mcp and puts its tools behind your own endpoint.

Agents find them with search_tools and run them with call_tool, so the Linear tool list is not loaded into context until it is needed.

Questions

Can I connect Linear read-only?

Yes. Linear runs mcp.linear.app/mcp/readonly, which only exposes read tools. Add that URL as a custom connector instead of the catalog entry.

Can I use a Linear API key instead of OAuth?

Linear accepts an API key as a bearer token. Add mcp.linear.app/mcp as a custom connector with an Authorization: Bearer header holding the key.

What about several Linear workspaces?

Linear gives each workspace its own sign-in, so each workspace is its own connection.
