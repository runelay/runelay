Conecte o Antigravity ao Runelay

O Runelay, gateway MCP open source, dá ao Antigravity um endpoint para todas as contas que você conectou. Adicione uma vez e o Antigravity enxerga as mesmas tools, skills e memórias dos seus outros agentes.

O que o Antigravity ganha

Sem um gateway, o Antigravity se conecta a cada servidor MCP por conta própria, carrega a lista inteira de tools de cada um e guarda os próprios logins.

Com o Runelay ele se conecta a um endpoint, /v1/mcp. O gateway guarda as credenciais e expõe poucas tools para buscar e chamar tudo que está atrás dele. No nosso benchmark foram 1.045 tokens de contexto na conexão para 125 tools (Runelay 0.3.2, 14 nov 2026, números completos).

Passo a passo

  1. 1

    Rode o Runelay

    Use o app desktop ou instale o servidor com Docker. Os dois servem o painel e o endpoint MCP na porta 4312.

    $curl -fsSL runelay.com/install | sh
  2. 2

    Crie uma chave

    No painel, o guia de configuração de agentes cria uma chave que começa com rnl_. Cada agente pode ter a própria chave, então dá para revogar uma sem mexer nas outras.

  3. 3

    Adicione ao mcp_config.json

    O arquivo global é o ~/.gemini/config/mcp_config.json, e o .agents/mcp_config.json de um workspace vale para um projeto. Para abrir, use View raw config em Manage MCP Servers na IDE, ou Copy Config File Path em Customizations no app. Troque a URL e a chave pelas suas. Com o app desktop a URL é http://127.0.0.1:4312/v1/mcp.

    {
  "mcpServers": {
    "runelay": {
      "serverUrl": "https://runelay.example.com/v1/mcp",
      "headers": { "Authorization": "Bearer rnl_..." }
    }
  }
}
  4. 4

    Ainda sem atalho na CLI

    runelay connect escreve no Claude Code, Codex, Cursor e Grok, não no Antigravity. Adicione o bloco acima à mão uma vez; a chave vale até você revogar no painel.

  5. 5

    Reinicie o Antigravity

    Salve o arquivo e abra o Antigravity de novo. O Runelay aparece na lista de MCP Servers com as tools dele.

Traga o que você já tem

runelay migrate ainda não lê o Antigravity, então os servidores MCP e os logins dele ficam onde estão. Adicione no painel do Runelay, pela URL, os servidores remotos que você usa e o Antigravity chega neles pelo endpoint. O arquivo do Gemini que o migrate lê, ~/.gemini/settings.json, é do Gemini CLI, não do Antigravity.

runelay push e runelay pull também não mexem nos arquivos do Antigravity. Memórias e skills chegam pelo endpoint, com search_context, read_memory e read_skill.

Depois de conectado, no Antigravity

  • search_tools e call_tool alcançam todas as contas conectadas, como Linear, GitHub e Notion.
  • execute encadeia várias chamadas num runtime JavaScript isolado.
  • search_context, read_memory e write_memory compartilham memória com os outros agentes.
  • read_skill entrega as mesmas skills para todos os agentes.

Perguntas

Os tokens das minhas contas chegam ao Antigravity?

Não. O Antigravity guarda só a chave do Runelay. Tokens OAuth e chaves de API ficam no seu servidor, criptografados com AES-256-GCM usando o seu RUNELAY_SECRET.

Preciso de Docker?

Não. O app desktop para Mac, Windows e Linux roda o mesmo servidor no seu computador. O Docker é para um servidor que fica sempre ligado.

Posso manter os servidores MCP que já configurei?

Sim. O Runelay é mais uma entrada no mcp_config.json e o resto do arquivo não muda. O runelay migrate não lê o Antigravity, então adicione esses servidores no painel do Runelay se quiser que todos os agentes os compartilhem.

Por que serverUrl?

O Antigravity lê servidores remotos em serverUrl e também aceita url; httpUrl não é suportado. O servidor remoto precisa falar Streamable HTTP, que é o que o endpoint do Runelay serve.
