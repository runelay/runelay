Conecte o Hermes Agent ao Runelay

O Runelay, gateway MCP open source, dá ao Hermes Agent um endpoint para todas as contas que você conectou. Adicione uma vez e o Hermes Agent enxerga as mesmas tools, skills e memórias dos seus outros agentes.

O que o Hermes Agent ganha

Sem um gateway, o Hermes Agent se conecta a cada servidor MCP por conta própria, carrega a lista inteira de tools de cada um e guarda os próprios logins.

Com o Runelay ele se conecta a um endpoint, /v1/mcp. O gateway guarda as credenciais e expõe poucas tools para buscar e chamar tudo que está atrás dele. No nosso benchmark foram 1.045 tokens de contexto na conexão para 125 tools (Runelay 0.3.2, 14 nov 2026, números completos).

Passo a passo

  1. 1

    Rode o Runelay

    Use o app desktop ou instale o servidor com Docker. Os dois servem o painel e o endpoint MCP na porta 4312.

    $curl -fsSL runelay.com/install | sh
  2. 2

    Crie uma chave

    No painel, o guia de configuração de agentes cria uma chave que começa com rnl_. Cada agente pode ter a própria chave, então dá para revogar uma sem mexer nas outras.

  3. 3

    Adicione ao ~/.hermes/config.yaml

    Esses bots costumam rodar num servidor para responder no chat o tempo todo, e um servidor não alcança o 127.0.0.1 do seu notebook. Rode o Runelay no mesmo servidor, ou em um lugar que o bot alcance por HTTPS. O Hermes lê servidores MCP remotos em mcp_servers, com a chave em headers. Troque a URL e a chave pelas suas. Com o app desktop a URL é http://127.0.0.1:4312/v1/mcp.

    mcp_servers:
  runelay:
    url: "https://runelay.example.com/v1/mcp"
    headers:
      Authorization: "Bearer rnl_..."
  4. 4

    Ainda sem atalho na CLI

    runelay connect escreve no Claude Code, Codex, Cursor e Grok, não no Hermes Agent. Adicione o Runelay à mão uma vez; a chave vale até você revogar no painel.

  5. 5

    Recarregue os servidores

    Rode /reload-mcp numa sessão do Hermes, ou reinicie o Hermes. Um gateway de mensagens rodando (hermes gateway run) pega a mudança sozinho em cerca de um minuto. As tools do Runelay aparecem como mcp_runelay_*.

Traga o que você já tem

runelay migrate ainda não lê o Hermes Agent, então os servidores MCP e os logins dele ficam onde estão. Adicione no painel do Runelay, pela URL, os servidores remotos que você usa e o Hermes Agent chega neles pelo endpoint.

runelay push e runelay pull também não mexem nos arquivos do Hermes Agent. Memórias e skills chegam pelo endpoint, com search_context, read_memory e read_skill.

Depois de conectado, no Hermes Agent

  • search_tools e call_tool alcançam todas as contas conectadas, como Linear, GitHub e Notion.
  • execute encadeia várias chamadas num runtime JavaScript isolado.
  • search_context, read_memory e write_memory compartilham memória com os outros agentes.
  • read_skill entrega as mesmas skills para todos os agentes.

Perguntas

Os tokens das minhas contas chegam ao Hermes Agent?

Não. O Hermes Agent guarda só a chave do Runelay. Tokens OAuth e chaves de API ficam no seu servidor, criptografados com AES-256-GCM usando o seu RUNELAY_SECRET.

Preciso de Docker?

Não. O app desktop para Mac, Windows e Linux roda o mesmo servidor no seu computador. O Docker é para um servidor que fica sempre ligado.

Posso manter os servidores MCP que já configurei?

Sim. O Runelay é mais um servidor MCP na configuração. Se você migrar os outros, runelay migrate --replace remove os migrados e deixa só o Runelay.

Posso esconder algumas tools do Runelay no Hermes?

Sim. Adicione um bloco tools na entrada runelay com include ou exclude, do mesmo jeito que você filtra qualquer servidor MCP no Hermes.
