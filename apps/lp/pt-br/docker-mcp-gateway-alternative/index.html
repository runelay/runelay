Uma alternativa ao Docker MCP Gateway sem Docker Desktop

O Runelay, gateway MCP open source, e o Docker MCP Gateway colocam vários servidores MCP atrás de um endpoint. O do Docker gira em torno do Docker Desktop e de containers; o Runelay roda como app desktop ou como um container. Esta página lista o que muda, com as fontes.

O Runelay serve quando

  • Você quer um gateway MCP sem instalar o Docker Desktop.
  • Os seus agentes devem dividir contas, skills e memória, não só tools.
  • Você já tem servidores MCP nos agentes e quer importar com runelay migrate.
  • Você quer um app desktop no computador ou um único container no servidor.

O Docker MCP Gateway serve quando

  • O seu time já usa o Docker Desktop e quer o MCP dentro dele.
  • Cada servidor MCP local deve rodar no próprio container, com CPU, memória e acesso a arquivos limitados.
  • Você quer servidores agrupados em perfis que podem ser compartilhados por registries OCI.
  • A sua empresa quer a oferta de AI Governance do Docker, que é só por convite pelo time de vendas.

Perguntas

Dá para usar um gateway MCP sem o Docker Desktop?

Sim. O app desktop do Runelay roda no Mac, Windows e Linux sem Docker nenhum. No servidor, o Runelay é um container em qualquer máquina com Docker. O plugin do gateway do Docker também instala à mão, mas a documentação dele parte do Docker Desktop com o MCP Toolkit.

O Runelay roda os servidores MCP em containers?

Não. O Runelay conecta URLs de MCP remoto, comandos locais e specs OpenAPI, e guarda as credenciais criptografadas na sua máquina. Se isolar cada servidor num container é obrigatório, o Docker MCP Gateway foi feito para isso.

Dá para sair do Docker MCP Gateway para o Runelay?

O Runelay aceita qualquer URL de MCP remoto, comando local ou spec OpenAPI, então você adiciona os servidores que usa um a um. O runelay migrate importa o que está configurado nos seus agentes, não os perfis do Docker.
