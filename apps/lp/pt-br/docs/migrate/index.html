runelay migrate

Um comando leva o que os seus agentes já têm para o Runelay, gateway MCP open source: servidores MCP, memórias, skills e instruções globais.

Como rodar

Rode no computador onde os agentes vivem, porque é lá que eles guardam os arquivos. Ele faz login pelo navegador se precisar, mostra um resumo por agente, pergunta uma vez e envia tudo para o seu servidor.

$curl -fsSL runelay.com/cli | sh
$runelay migrate

O que acontece com cada servidor MCP

ResultadoQuais
Contas OAuth com token legívelChegam conectadasGrok; Codex e Claude Code no Keychain do macOS
Servidores que usam headersChegam conectadosQualquer agente
Outras contas OAuthFila de reconexão no painelInclui o Cursor, que criptografa os tokens
Servidores de comando local (stdio)Ficam no agenteAdicione pelo painel se precisar

Opções e comandos relacionados

O que faz
runelay migrate --yesPula a pergunta. Obrigatório sem terminal.
runelay migrate --replaceRemove dos agentes os MCPs migrados e deixa só o Runelay.
runelay importSó transforma em conexões os servidores MCP das configurações.
runelay pushEnvia memórias, skills e instruções globais.
runelay pullEscreve o resumo compartilhado e as skills novas de volta nos agentes.
runelay connectRegistra o Runelay no Claude Code, Codex, Cursor e Grok.

Vale saber

  • Os tokens vão só para o seu servidor e ficam criptografados.
  • Muitos provedores trocam o refresh token a cada uso. Depois que o Runelay renova, a entrada antiga do agente pode pedir login de novo; --replace evita isso.
  • Desde a 0.3.4, rodar runelay migrate de novo não mexe nas conexões que já funcionam.
  • runelay pull só edita o bloco entre os marcadores do Runelay no CLAUDE.md e no AGENTS.md.

Perguntas

Quais agentes o migrate lê?

Claude Code, Codex, Cursor, Grok, Gemini e OpenCode.

Ele apaga algo dos meus agentes?

Por padrão, não. Só o --replace remove os servidores MCP que ele migrou.

Dá para rodar em CI?

Use runelay migrate --yes, com RUNELAY_URL e RUNELAY_API_KEY apontando para uma chave criada no painel.
