Uma alternativa ao MCPHub para os seus agentes

O Runelay, gateway MCP open source, e o MCPHub colocam vários servidores MCP atrás de um endpoint. O MCPHub é um hub com painel web, grupos e usuários, que costuma rodar no Docker; o Runelay roda como app desktop ou um container e também divide skills e memória entre os agentes. Esta página lista o que muda, com as fontes.

O Runelay serve quando

  • São os seus agentes que precisam de um endpoint MCP, e você quer um app desktop sem Docker.
  • Os seus agentes devem dividir contas, skills e memória, não só tools.
  • Você quer adicionar uma API pela spec OpenAPI, ou conectar Google e GitHub em um clique.
  • Você já tem servidores MCP nos agentes e quer importar com runelay migrate.

O MCPHub serve quando

  • Você quer um painel web para adicionar, ligar e acompanhar servidores MCP, com logs, latência e health check.
  • Times ou projetos diferentes devem ter o próprio grupo de servidores e tools, cada um no seu endpoint.
  • Os agentes devem achar tools pelo significado com o Smart Routing, usando PostgreSQL, pgvector e uma API de embeddings compatível com a OpenAI.
  • Várias pessoas entram com GitHub, Google ou o seu provedor OIDC, cada uma com as próprias credenciais.

Perguntas

O Runelay é um fork do MCPHub?

Não. O Runelay é um projeto MIT separado, escrito com Bun, Hono, SQLite e React. O MCPHub é um projeto Apache 2.0 escrito em TypeScript.

Preciso de Docker para rodar um hub MCP?

Com o Runelay, não: o app desktop roda no Mac, Windows e Linux e, no servidor, é um container. O MCPHub recomenda Docker e também roda do código-fonte com Node.js 22.

Dá para sair do MCPHub para o Runelay?

O Runelay aceita qualquer URL de MCP remoto, comando local ou spec OpenAPI, então você adiciona os servidores que usa um a um. O runelay migrate importa o que está configurado nos seus agentes, não o mcp_settings.json do MCPHub.
