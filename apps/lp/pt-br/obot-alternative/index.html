Uma alternativa leve ao Obot

O Runelay, gateway MCP open source, e o Obot colocam servidores MCP atrás de um endpoint controlado. O Obot é uma plataforma para organizações, com Kubernetes em produção; o Runelay é para os agentes de uma pessoa, como app desktop ou um container. Esta página lista o que muda, com as fontes.

O Runelay serve quando

  • São os seus agentes, não a empresa inteira, que precisam de um endpoint MCP.
  • Você quer um app desktop ou um único container, não um cluster Kubernetes.
  • Os seus agentes devem dividir memória, além de contas e skills.
  • Você já tem servidores MCP nos agentes e quer importar com runelay migrate.

O Obot serve quando

  • Muitos usuários precisam de acesso controlado por pessoa ou por grupo do provedor de identidade.
  • Você precisa de SSO com Entra, Okta ou outro provedor corporativo, e provisionamento por SCIM.
  • Você quer gateway de LLM e gateway MCP na mesma plataforma.
  • Você roda Kubernetes e quer os servidores MCP como workloads ali, ou o Obot Cloud hospedado.

Perguntas

O Runelay é um fork do Obot?

Não. O Runelay é um projeto MIT separado, escrito com Bun, Hono, SQLite e React.

Preciso de Kubernetes para hospedar um gateway MCP?

Com o Runelay, não: o app desktop roda no seu computador e, no servidor, é um container em qualquer máquina com Docker. O Obot também roda com Docker para avaliação e recomenda Kubernetes em produção e em instalações multi-tenant.

Dá para sair do Obot para o Runelay?

O Runelay aceita qualquer URL de MCP remoto, comando local ou spec OpenAPI, então você adiciona os servidores que usa um a um. O runelay migrate importa o que está configurado nos seus agentes, não o que está guardado dentro do Obot.
