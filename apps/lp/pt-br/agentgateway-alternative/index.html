Uma alternativa ao agentgateway para os seus agentes

O Runelay, gateway MCP open source, e o agentgateway colocam servidores MCP atrás de um endpoint. O agentgateway é um proxy escrito em Rust para tráfego MCP, A2A e de LLM, configurado por arquivo ou no Kubernetes; o Runelay é um app para os agentes de uma pessoa, com catálogo, skills e memória. Esta página lista o que muda, com as fontes.

O Runelay serve quando

  • Você quer um app com catálogo e login nas suas contas em um clique, não um proxy para configurar.
  • Os seus agentes devem dividir contas, skills e memória, não só tools.
  • Você quer um app desktop no computador ou um único container no servidor.
  • Você já tem servidores MCP nos agentes e quer importar com runelay migrate.

O agentgateway serve quando

  • Você quer um proxy só, escrito em Rust, para tráfego MCP, A2A e de LLM, com API compatível com a OpenAI entre provedores.
  • O acesso precisa seguir políticas finas: JWT, chaves de API, RBAC com CEL, rate limit, CORS e TLS.
  • Você roda Kubernetes e quer configurar pelo Gateway API, com métricas, logs e tracing no OpenTelemetry.
  • Você precisa de guardrails e controle de gasto com LLM, ou de roteamento para modelos próprios por uso de GPU e KV cache.

Perguntas

O Runelay é feito em cima do agentgateway?

Não. O Runelay é um projeto MIT separado, escrito com Bun, Hono, SQLite e React. O agentgateway é um projeto Apache 2.0 escrito em Rust e mantido na Linux Foundation.

Preciso de Kubernetes para rodar um gateway MCP?

Com o Runelay, não: o app desktop roda no seu computador e, no servidor, é um container. O agentgateway também roda como binário standalone ou no Docker, e tem um modo Kubernetes com o Gateway API.

Dá para sair do agentgateway para o Runelay?

O Runelay aceita qualquer URL de MCP remoto, comando local ou spec OpenAPI, então você adiciona os servidores que usa um a um. O runelay migrate importa o que está configurado nos seus agentes, não um arquivo de config do agentgateway.
